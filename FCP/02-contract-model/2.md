## Як користуватися Contract Model

---

### 1. Ієрархія контрактів

```
ContractTemplate  →  ContractOffer  →  PlayerContract
   (contracts.yml)     (DB / дошка)      (DB / гравець)
```

- **ContractTemplate** — статичний архетип у `contracts.yml`. Визначає матеріали, ранг, нагороду, `max-simultaneous-players`.
- **ContractOffer** — live-інстанція, прив'язана до конкретної дошки. Зберігає скільки гравців зараз виконують (`activePlayers`).
- **PlayerContract** — персональний запис гравця. Має **власну копію** вимог (`requirements`) з поточним прогресом.

---

### 2. Scope контрактів

| Scope | Видимість | Час дії | Спосіб здачі |
|-------|-----------|---------|--------------|
| `LOCAL` | Лише ця дошка | 15 хв | ПКМ по цій дошці з предметами |
| `REGIONAL` | Всі дошки регіону | 60 хв | ПКМ по будь-якій дошці регіону |
| `GLOBAL` | Всі дошки сервера | 4 год | Через GUI `/contracts` |

---

### 3. Прийняти контракт (гравець)

**LOCAL / REGIONAL:**
1. ПКМ по дошці (порожня рука) → відкривається GUI
2. Знайди контракт у списку → натисни для деталей
3. У вікні деталей відображається:
   - Кількість вільних місць: `"Slots available: X/Y"`
   - Кнопка **Accept Contract** (зелений барвник) — якщо є вільні місця
4. Клік по кнопці → `PlayerContract` створюється з особистою копією вимог
5. `activePlayers` оффера збільшується на 1 (слот зайнятий)
6. Якщо всі місця зайняті — відображається сіра бар'єрна плашка

**GLOBAL:**
1. Відкрий `/contracts` → секція `Global Contracts`
2. Обери оффер → деталі → **Accept Contract**
3. GLOBAL-оффер можна прийняти лише **один раз** за весь час (навіть після виконання повторно не доступно)

---

### 4. Здача предметів на дошці (LOCAL / REGIONAL)

```
1. Візьми потрібний предмет у руку
2. ПКМ по будь-якому блоку активної дошки
3. Система знаходить твій активний PlayerContract для цієї дошки
   (перший контракт, що приймає цей матеріал)
4. Знімає предмети з руки (до залишку вимоги)
5. Оновлює progress у PersonalContract.requirements
6. Якщо всі requirements виконані → автоматична нагорода
```

> **Часткова здача** дозволена за замовчуванням (`partial-delivery: true`).
> Якщо відключена — потрібно мати весь залишок в руці одразу
> (помилка: `"This contract requires the full remaining amount in one turn-in."`).

---

### 5. Deathless-бонус

- Якщо від моменту прийняття контракту гравець **не помирав** → нагорода множиться на коефіцієнт `no-death-money-multiplier` (у `contracts.yml`)
- Повідомлення при отриманні: `"No-death bonus applied: +X% coins"`
- Смерть знімає прапорець `deathless` і бонус втрачається

---

### 6. Здача GLOBAL-контракту (через GUI)

```
1. Відкрий /contracts → секція "Your Active Contracts"
2. Або: знайди той самий оффер → деталі → кнопка Submit
3. Система перевіряє весь інвентар (не лише руку)
4. Якщо всього достатньо → знімає предмети → нарахована нагорода
```

---

### 7. Відмовитися від контракту

```
/contracts abandon <offer_id>
```

- Статус контракту → `FAILED`
- Нараховується штраф репутації (`reputation-on-abandon` у `config.yml`)
- `activePlayers` у відповідному `ContractOffer` зменшується на 1
- Слот звільняється для іншого гравця

---

### 8. Закінчення часу (expiration)

- При закінченні дедлайну `PlayerContract` переходить у статус `FAILED`
- Гравець отримує повідомлення, якщо він онлайн: `"Contract failed due to expiration: <title>"`
- `activePlayers` оффера зменшується автоматично
- Інтервал перевірки задається у `config.yml` → `cleanup-interval-minutes`

---

### 9. Контракти типу CONSTRUCTION

- Здаються через ПКМ по дошці так само, як DELIVERY
- Для road-проектів додатково перевіряється фізична картина блоків у світі
- `completeBoardOffer()` запускається також при зміні блоку у зоні `ConstructionSite`
- Якщо блоки збудовані коректно — контракт закривається автоматично без ПКМ

---

### 10. Команди гравця

| Команда | Опис |
|---------|------|
| `/contracts` | Відкрити GUI зі списком офферів |
| `/contracts active` | Переглянути активні контракти |
| `/contracts abandon <id>` | Відмовитися від контракту |
| `/contracts submit` | Здати всі готові GLOBAL-контракти разом |

---

### 11. Адмін-команди Contract Model

| Команда | Опис |
|---------|------|
| `/contracts admin reload` | Перезавантажити `contracts.yml` та `config.yml` |
| `/contracts admin board refresh <id>` | Примусово перегенерувати оффери на дошці |
| `/contracts admin regenerate` | Перегенерувати всі оффери всіх дошок |

---

### 12. Налаштування у contracts.yml

```yaml
archetypes:
  timber_consignment:
    max-simultaneous-players: 3   # скільки гравців приймають одночасно (default: 1)
    partial-delivery: true         # чи дозволена часткова здача
    ranks: [F, E, D, C, B]
    scopes: [LOCAL, REGIONAL]

settings:
  default-no-death-money-multiplier: 1.2   # множник нагороди без смерті
```

> Дані офферів (activePlayers, expiresAt, requirements) зберігаються у БД — **не редагуй вручну**.

---

### 13. Дозволи

| Permission | Default | Опис |
|---|---|---|
| `frontiercontracts.use` | all | Прийняття, здача, перегляд контрактів |
| `frontiercontracts.admin` | op | Reload, refresh, regenerate |
