## Як користуватися Construction Module

---

### 1. Що таке будівельний контракт

Будівельний контракт (тип `CONSTRUCTION`) — це проектний контракт, де гравець мусить **збудувати реальну конструкцію у світі**, а не здати предмети на дошку. Виконання перевіряється за фізичним станом блоків у грі.

Два підтипи:

| Підтип | Опис |
|--------|------|
| **ROAD** | Прокласти дорогу: вказані тайли повинні містити потрібний матеріал і стояти на твердій основі |
| **BUILDING** | Збудувати будівлю: визначена 3D зона (AABB) повинна містити достатню кількість вказаних матеріалів |

---

### 2. Прийняти будівельний контракт (гравець)

1. ПКМ по дошці порожньою рукою → відкрити GUI
2. Обрати будівельний контракт → деталі → натиснути **Accept Contract**
3. Одразу після прийняття у чаті з'являється повідомлення з координатами площадки:

   ```
   Build site: 123, 64, -456
   ```

4. Прямуй на вказані координати та будуй

---

### 3. Виконання ROAD-контракту

```
1. Знайди площадку дороги за координатами з чату
2. Поклади блоки потрібного матеріалу на кожен тайл
3. Тайл зараховується лише якщо:
   - матеріал блоку == required surface
   - блок прямо під тайлом є твердим (не повітря, не вода)
4. Клікни ПКМ лопатою по площадці → actionbar показує поточний прогрес
5. Коли всі тайли заповнені → контракт завершується автоматично
```

---

### 4. Виконання BUILDING-контракту

```
1. Знайди ділянку будівництва за координатами з чату
2. Будуй всередині виділеної 3D зони (AABB)
3. Кожного разу коли кладеш блок:
   - Через 1 тік сервер підраховує всі блоки потрібних матеріалів у AABB
   - Оновлює прогрес кожної вимоги (deliveredAmount)
4. Клікни ПКМ лопатою по блоку в зоні → actionbar показує % виконання
5. Коли всі вимоги виконані → контракт завершується автоматично
```

> Рахуються **всі** блоки потрібного матеріалу в AABB, незалежно від того, хто їх поклав. Це дозволяє кооперативне будівництво (`public-construction-projects: true`).

---

### 5. Actionbar прогрес

Правий клік лопатою по будь-якому блоку в зоні будівництва:

```
Build: 73%
```

Відображає агрегований відсоток виконання всіх вимог контракту.

---

### 6. Авто-перевірка (Scheduled Check)

Навіть без взаємодії гравця, сервер автоматично перевіряє всі активні будівельні контракти кожні 60 секунд (налаштовується у `config.yml`). Якщо контракт виконано і гравець онлайн — нагорода нараховується автоматично.

Якщо гравець офлайн — прогрес зберігається, і контракт завершиться щойно він зайде і взаємодіє з площадкою.

---

### 7. Режим Creative — захист від зловживань

Якщо у `config.yml` встановлено `anti-abuse.block-creative-submit: true`, блоки розставлені у Creative-режимі **не враховуються** для будівельних контрактів.

---

### 8. Відображення на знаку дошки

Знак будівельного контракту показує:

- Рядок 1–2: назва проекту (або "Build")
- Рядок 3: прогрес вимог у форматі, заданому у `contracts.yml`
  - Приклад: `2/4 req` або `50%`
- Рядок 4: мітка "Build"

Формат рядка 3 задається через `construction-rules.sign-progress-format` у `contracts.yml`.

---

### 9. Алгоритм вибору площадки (ConstructionSitePlanner)

Планувальник автоматично шукає місце для будівництва навколо bell дошки:

```
BUILDING:
1. Перебирає 4 кардинальних напрямки (N/E/S/W)
2. Для кожного: відступає на 6 блоків від bell, формує footprint 7×7 (або 9×9 для 2+ поверхів)
3. Відхиляє, якщо:
   - висота поверхні коливається > 2 блоків (нерівна місцевість)
   - у footprint є блоки структури дошки
   - відстань до іншого активного сайту < 15 блоків
4. Обирає перший напрямок, що пройшов всі перевірки

ROAD:
1. Перебирає 4 кардинальних напрямки
2. Для кожного: будує список тайлів прямою лінією від bell
3. Відхиляє напрямок, якщо будь-який тайл перетинається з тайлами існуючих ROAD-сайтів
4. Обирає перший вільний напрямок
```

---

### 10. Налаштування в contracts.yml

```yaml
construction-rules:
  allow-multi-material-turn-in: true
  complete-only-when-all-requirements-met: true
  public-construction-projects: true
  sign-progress-format: "{done}/{total} req"   # або "{pct}%"
  wheat-per-floor: 3

archetypes:
  # Приклад ROAD-контракту
  cobblestone_road:
    type: CONSTRUCTION
    title: "Дорога з бруківки"
    metadata:
      surface: COBBLESTONE
      road-tiles: 10
      recommended-tool: STONE_PICKAXE
    requirements:
      - material: COBBLESTONE
        amount: 10
    rewards:
      money: 150.0

  # Приклад BUILDING-контракту
  storage_shed:
    type: CONSTRUCTION
    title: "Комора"
    metadata:
      building: STORAGE_SHED
      floors: 1
    requirements:
      - material: OAK_PLANKS
        amount: 32
      - material: OAK_LOG
        amount: 16
    rewards:
      money: 400.0
```

---

### 11. Налаштування в config.yml

```yaml
construction:
  check-interval-seconds: 60   # інтервал авто-перевірки будівельних контрактів (секунди)

anti-abuse:
  block-creative-submit: true   # блокувати прогрес від блоків, покладених у Creative-режимі
```
