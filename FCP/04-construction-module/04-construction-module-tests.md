## ConstructionSitePlanner

### CSP-01 — BUILDING: повертає сайт у вільному плоскому місці
- [ ] Виконано
- **Кроки:** Поруч з дошкою є плоска вільна ділянка в одному з 4 кардинальних напрямків. Дошка генерує будівельний контракт.
- **Очікується:** Контракт отримує ConstructionSite з ненульовими координатами; у чаті після прийняття видно координати площадки.

### CSP-02 — BUILDING: відхилення висоти > 2 → напрямок пропускається
- [ ] Виконано
- **Кроки:** Пагорб або яр у всіх напрямках від дошки (висота коливається більш ніж на 2 блоки). Дошка намагається згенерувати будівельний контракт.
- **Очікується:** Контракт не генерується (сайт не знайдено); сервер не падає, помилок у консолі немає.

### CSP-03 — BUILDING: відстань до наявного сайту < 15 блоків → напрямок пропускається
- [ ] Виконано
- **Кроки:** Поруч вже є активний будівельний контракт в радіусі 15 блоків. Дошка генерує ще один будівельний контракт.
- **Очікується:** Новий сайт знаходиться більш ніж на 15 блоків від вже існуючого.

### CSP-04 — BUILDING: блоки структури дошки не потрапляють у footprint
- [ ] Виконано
- **Кроки:** Один кардинальний напрямок від дошки впирається у знаки або блоки самої структури. Генерується будівельний контракт.
- **Очікується:** Сайт обирається у напрямку без конфлікту зі структурою дошки.

### CSP-05 — ROAD: повертає тайли у кардинальному напрямку від bell
- [ ] Виконано
- **Кроки:** Дошка на відкритому місці. Генерується ROAD-контракт на 5 тайлів.
- **Очікується:** Контракт отримує 5 тайлів, розташованих прямою лінією в одному з напрямків (N/E/S/W).

### CSP-06 — ROAD: тайли існуючих Road-сайтів потрапляють у заблокований список
- [ ] Виконано
- **Кроки:** Вже є активний ROAD-контракт з певними тайлами. Генерується ще один ROAD-контракт.
- **Очікується:** Новий маршрут не перетинається з тайлами вже існуючого ROAD-сайту.

## ConstructionValidator — ROAD

### CV-R-01 — Всі тайли правильного матеріалу на твердій основі → повертає true
- [ ] Виконано
- **Кроки:** Гравець прийняв ROAD-контракт (surface = COBBLESTONE, 5 тайлів). Поклав COBBLESTONE на кожен тайл на твердій підлозі. Клікнув ПКМ лопатою.
- **Очікується:** Контракт завершується; гравець отримує нагороду та повідомлення у чаті.

### CV-R-02 — Один тайл неправильного матеріалу → повертає false
- [ ] Виконано
- **Кроки:** 4 з 5 тайлів покриті COBBLESTONE, один — STONE. Гравець клікає ПКМ лопатою.
- **Очікується:** Контракт НЕ завершується; actionbar показує прогрес < 100%.

### CV-R-03 — Тайл правильного матеріалу без твердого блоку знизу → повертає false
- [ ] Виконано
- **Кроки:** Гравець поклав COBBLESTONE на тайл дороги, але видалив блок прямо під ним (тайл "висить у повітрі"). Клікає ПКМ лопатою.
- **Очікується:** Тайл не зараховується; контракт НЕ завершується.

### CV-R-04 — Тайл у вивантаженому world → повертає false без crash
- [ ] Виконано
- **Кроки:** ROAD-контракт зареєстрований, але world вивантажений. Scheduled check запускається.
- **Очікується:** Перевірка пропускається тихо; сервер не падає.

### CV-R-05 — ROAD повністю завершено через shovel-interact → completeBoardOffer
- [ ] Виконано
- **Кроки:** Гравець укладає останній тайл дороги. Клікає ПКМ лопатою.
- **Очікується:** Контракт автоматично завершується; знаки на дошці оновлюються; нагорода нарахована.

## ConstructionValidator — BUILDING

### CV-B-01 — AABB містить достатньо блоків вимог → повертає true
- [ ] Виконано
- **Кроки:** Гравець прийняв будівельний контракт (32 OAK_PLANKS). Поклав 32 OAK_PLANKS в межах AABB. Кладе ще один довільний блок (тригер).
- **Очікується:** Контракт завершується; нагорода нарахована.

### CV-B-02 — Недостатньо блоків → deliveredAmount оновлено, повертає false
- [ ] Виконано
- **Кроки:** Гравець поклав 15 OAK_PLANKS з 32 необхідних. Кладе ще один блок.
- **Очікується:** Контракт не завершується; знак дошки показує оновлений прогрес (наприклад 15/32 або відповідний відсоток).

### CV-B-03 — Блоки поза AABB не рахуються
- [ ] Виконано
- **Кроки:** Гравець поклав 20 OAK_PLANKS всередині AABB і ще 20 поза нею. Кладе тригерний блок.
- **Очікується:** Рахуються лише 20 блоків в межах AABB; контракт не завершується.

### CV-B-04 — Multi-requirement: кожна вимога рахується окремо
- [ ] Виконано
- **Кроки:** Контракт вимагає 16 OAK_LOG та 32 OAK_PLANKS. Гравець поклав 16 OAK_LOG та лише 20 OAK_PLANKS. Кладе тригерний блок.
- **Очікується:** OAK_LOG — 16/16 (виконано), OAK_PLANKS — 20/32 (не виконано); контракт не завершується.

### CV-B-05 — Всі вимоги виконані через BlockPlaceEvent → completeBoardOffer
- [ ] Виконано
- **Кроки:** Гравець поклав усі необхідні блоки. Кладе останній блок довільного матеріалу.
- **Очікується:** Через 1 тік контракт завершується; знаки дошки оновлюються; нагорода нарахована.

### CV-B-06 — World не завантажений → повертає false без crash
- [ ] Виконано
- **Кроки:** BUILDING-контракт зареєстрований, але world вивантажений. Scheduled check запускається.
- **Очікується:** Перевірка пропускається тихо; сервер не падає.

## ConstructionWorldListener

### CWL-01 — BlockPlaceEvent: блок в AABB → перевірка виконується з 1-тік затримкою
- [ ] Виконано
- **Кроки:** Гравець кладе блок точно в межах AABB активного будівельного контракту.
- **Очікується:** Через 1 тік сервер виконує перевірку; знак дошки оновлює прогрес.

### CWL-02 — BlockPlaceEvent: блок поза AABB → перевірка не торкається цього сайту
- [ ] Виконано
- **Кроки:** Гравець кладе блок поруч з AABB, але зовні.
- **Очікується:** Прогрес будівельного контракту не змінюється.

### CWL-03 — Creative mode + block-creative-submit: true → перевірка пропускається
- [ ] Виконано
- **Кроки:** У `config.yml` встановлено `block-creative-submit: true`. Гравець переходить у Creative режим і кладе блок в AABB.
- **Очікується:** Контракт не прогресує; знак дошки не оновлюється.

### CWL-04 — Creative mode + block-creative-submit: false → перевірка виконується
- [ ] Виконано
- **Кроки:** У `config.yml` встановлено `block-creative-submit: false`. Гравець у Creative кладе блок в AABB.
- **Очікується:** Перевірка виконується нормально; прогрес оновлюється.

### CWL-05 — Shovel ПКМ на блоку в AABB → actionbar з відсотком прогресу
- [ ] Виконано
- **Кроки:** Гравець тримає лопату і клікає ПКМ по блоку всередині AABB активного контракту.
- **Очікується:** З'являється actionbar у форматі `Build: 50%` (відсоток відображає поточний агрегований прогрес).

### CWL-06 — Shovel ПКМ за межами будь-якого сайту → actionbar не з'являється
- [ ] Виконано
- **Кроки:** Гравець клікає лопатою на випадковий блок далеко від будь-якого сайту.
- **Очікується:** Жодного actionbar від плагіна; стандартна ванільна поведінка лопати.

### CWL-07 — Shovel ПКМ по повітрю → подія ігнорується
- [ ] Виконано
- **Кроки:** Гравець клікає лопатою у порожній простір (clicked block = null або AIR).
- **Очікується:** Плагін ігнорує подію; жодних помилок у консолі.

## ContractService — Construction

### CS-CN-01 — accept() → повідомлення з координатами сайту
- [ ] Виконано
- **Кроки:** Гравець приймає будівельний контракт, у якого є визначений ConstructionSite.
- **Очікується:** Одразу після прийняття у чаті повідомлення з координатами (X, Y, Z) площадки будівництва.

### CS-CN-02 — accept() без сайту → без повідомлення координат
- [ ] Виконано
- **Кроки:** Будівельний контракт існує, але sitePlanner не зміг знайти місце (site = null). Гравець приймає контракт.
- **Очікується:** Контракт прийнятий без повідомлення про координати; жодних NPE у логах.

### CS-CN-03 — checkConstructionCompletions: block не в жодному сайті → повертає 0
- [ ] Виконано
- **Кроки:** Гравець кладе блок далеко від будь-якого будівельного сайту.
- **Очікується:** Метод повертає 0; жодних нагород не нараховується.

### CS-CN-04 — checkConstructionCompletions: offer вже complete → пропускається
- [ ] Виконано
- **Кроки:** Вже завершений будівельний контракт (offer.isComplete() = true). Гравець кладе блок у той самий AABB.
- **Очікується:** Повторне завершення не відбувається; нагорода не нараховується двічі.

### CS-CN-05 — runScheduledConstructionChecks: онлайн гравець з виконаним контрактом → completeBoardOffer
- [ ] Виконано
- **Кроки:** Будівельний контракт повністю виконано. Гравець онлайн. Очікуємо наступного scheduled check (макс. 60 сек).
- **Очікується:** Контракт завершується автоматично; нагорода нарахована; гравець отримує повідомлення у чаті.

### CS-CN-06 — runScheduledConstructionChecks: гравець офлайн → без завершення, без crash
- [ ] Виконано
- **Кроки:** Будівельний контракт повністю виконано, але гравець вийшов з сервера. Scheduled check запускається.
- **Очікується:** Прогрес збережено у DB; завершення не відбувається; помилок у консолі немає. Після входу і взаємодії з площадкою контракт завершиться.

### CS-CN-07 — generateProjectOffer: sitePlanner отримує activeConstructionSites
- [ ] Виконано
- **Кроки:** Вже є 2 активних будівельних контракти в різних місцях. Генерується третій.
- **Очікується:** Третій сайт не перетинається з першими двома (відстань > 15 блоків, або обраний інший напрямок).

## StorageService — Construction

### SS-CN-01 — site_blob roundtrip: ConstructionSite серіалізується та десеріалізується коректно
- [ ] Виконано
- **Кроки:** Гравець приймає будівельний контракт з ConstructionSite. Сервер перезапускається.
- **Очікується:** Після перезапуску у гравця залишається той самий контракт з тими самими координатами сайту; площадка визначається правильно.

### SS-CN-02 — road tiles roundtrip: список тайлів відновлюється
- [ ] Виконано
- **Кроки:** ROAD-контракт зі списком 5 тайлів. Сервер перезапускається.
- **Очікується:** Після перезапуску у контракті рівно 5 тайлів на тих самих координатах; ROAD-валідація продовжує працювати.

### SS-CN-03 — deliveredAmount у requirements_blob зберігається між перезапусками
- [ ] Виконано
- **Кроки:** Гравець поклав 20 з 32 OAK_PLANKS у будівельному контракті. Сервер перезапускається.
- **Очікується:** Після перезапуску знак дошки показує оновлений прогрес (20/32 або відповідний відсоток); прогрес не скидається до нуля.

### SS-CN-04 — site_blob порожній → decodeSite повертає null без exception
- [ ] Виконано
- **Кроки:** У базі даних є запис оффера без site_blob (наприклад, старий запис до появи будівельних контрактів). Сервер завантажується.
- **Очікується:** Оффер завантажується, site = null; сервер не падає; контракт ігнорується при валідації.
